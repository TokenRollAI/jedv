# 附件保留与工作区交接

附件拥有 opaque ID、本地 staging、保留租期和原生会话交接，不只是普通 Files 编辑。staging 对象、工作区副本与消息历史分别拥有生命周期，清理其中一项不能推断另外两项已消失。

## 本地身份与完成可见性

upload、read、delete 和 materialize 都经过 host 认证，客户端使用 UUID attachmentId，不指定 staging 真实路径。store 由 host manifest 目录或独立运行的应用 home 定位；旧 per-org 命名不代表存在产品云组织 ACL 或逐 viewer 隔离。复制目标仍由 workspace 持久记录解析，附件 ID 不授予任意工作区路径权限。

inline base64 上传在解码分配前先估算尺寸，空 decoded payload 拒绝；未知 MIME 降级为 binary。单次附件数量、inline bytes 和图像预算由 shared policy 统一，客户端提前提示，host 再验证。不能依赖客户端校验作为 API 防线，也不能将一般附件大小上限误当 inline 传输预算。

staging 先写 bytes，最后发布 metadata。resolver 先读 metadata 再确认 bytes 存在，因此 metadata-last 是完成可见性的约定，不能为了流式写入提前发布。目录和文件使用限制性权限。

## 上传附件什么时候删除

read、materialize 和 native resolver 等交出入口统一经过 handOutAttachment，刷新 lastUsedAt。保留期从最后使用计算，而非上传时刻。旧记录缺少 lastUsedAt 时首次 sweep 先 stamp 并给予完整保留期，不能直接按 createdAt 删除旧用户数据。

sweep 从 metadata 读取到 rename claim 保持同步，防止同一 event loop 的 handout 夹在过期判断和 claim 之间。claim 把对象改为不可通过原 ID 访问的 sweeping 名称，随后慢递归删除才异步执行。重启后继续清理遗留 sweeping 目录；fileId 索引目录不作为普通附件遍历。

删除索引前确认它仍指向当前对象，避免旧对象清理破坏新的映射。显式 delete 幂等成功，不证明 ID 原来存在。删除 staging 不会自动删除已复制到工作区的文件，也不改写聊天历史。

## 同名附件与部分失败

交给 Agent 的工作区副本放在 `.jedv/attachments`，返回 worktree-relative path。writer 与 prompt renderer 必须共用命名规则，否则提示会引用不存在的文件。批次内按大小写不敏感去重，但历史文件和并发发送仍需在真实目录用 exclusive `wx` claim，再按 suffix 重试；不能用 exists-check 后覆盖写入。

附件目录的 `.gitignore` 采用 create-only，保留用户已有编辑。终端上传先 staging 再 materialize；原生 prompt 的复制适配保存返回的实际路径，不能根据原始文件名重新猜路径。

materialize 逐项 handout、claim、copy，没有整批事务或自动回滚保证。后项失败可能保留前项副本；请求结果未知也不等于复制未发生。调用方必须保留这种不确定性，不能盲重试后把重复副本误认为新的用户输入。

## 原生Agent如何读取attachmentId

Chat resolver 优先兼容 fileId lookup，否则使用 attachmentId，每次交出同样刷新租期。图像返回本地 path、MIME 与 base64，其他附件返回 path 而不继续 inline bytes。缺失或读取异常返回 null 并按错误路径报告，不自动从云下载，也不伪造有效文件。

Agent 输出图片走另一条存储链：只接受有限、非空的 regular file 或 bytes，在工作区附件目录用内容 hash 命名。replay reference 可保持历史引用对应原图，避免原始路径后来内容变化使旧消息展示新图。这些工作区输出不属于 staging 的 lastUsedAt sweep 对象。

## 权威锚点

- `packages/host-service/src/trpc/router/attachments/storage.ts`、`sweep.ts`：metadata-last、交出租期和同步 claim。
- `packages/shared/src/workspace-attachments.ts` 与 host `attachments.ts`：跨调用方命名和真实目录独占。
- `packages/host-service/src/chat-v3/resolveAttachment.ts`、`agentImages.ts`：原生输入与输出图片的不同生命周期。
