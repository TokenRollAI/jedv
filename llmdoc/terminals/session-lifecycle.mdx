# PTY 会话、重连与端口归属

PTY daemon 持有 shell 和 master fd；host 持工作区会话元数据、attachments 与事件；renderer 持显示状态和较长 scrollback。关闭窗口或 host transport 不等于关闭 shell，活跃列表需将 daemon truth 与 host DB 的 active workspace 身份相连，不能只看本进程 attachment map。

## daemon 与 dispose 权限

daemon 保存有界内存 replay ring，不负责完整持久 scrollback。DaemonClient dispose 只关客户端 socket；pending request timeout/断开必须明确失败，不能 resolve 成成功。

Unix socket 协议分开 JSON header 与 binary PTY payload，并有版本协商、socket 权限与受信 supervisor。FD handoff 成功后 predecessor 必须以 killSessions=false 退出，避免杀死已经转移的用户 shell；普通 daemon shutdown 才清理自身 PTY。

macOS 的 `detached`/`unref` 不会解除应用 coalition 责任，另一个 Host adopt 也不会改变系统归属。新 daemon 因此由独立的临时 LaunchAgent job 承载，不写登录自启目录；KeepAlive 关闭，由 Supervisor 保持重启权限。job 的 AbandonProcessGroup 保护 handoff 后仍活着的 successor。当前默认依赖 `gui/<uid>` 登录域，没有可用域时明确失败，不回落到可能随旧应用退出的 detached 启动；不能据此承诺无 GUI 登录的纯 SSH 路径。

job 以 profile/org namespace、UID/domain 和 generation 共同标识，manifest 的可选 job identity 与 hello 中的 generation 用于交叉核对。启动结果不确定时保留记录，禁止换 label 重试。stop、清理与 handoff 都复核同代资源；只有确认目标 PID 已死、socket 不活且没有 handoff claim 才卸载该 job。predecessor 退出至 successor 重绑间以持久 handoff 屏障保护，不能把这段空窗当死资源清理。既有活 daemon 只 adopt，不为升级启动机制强制迁移。

开发主进程重载默认也 adopt 活 daemon。强制重建是显式开发开关，具有结束终端的后果；不能把每次重载当作清理“残留”的授权。

显式 dispose 先持久化 disposeRequestedAt 再尝试 kill；失败保留可重试意图，未知 session 可幂等视作已清理。reaper 区分 exited（Agent 可能恢复）与用户 disposed（不得复活），以 grace 与重复 missing 观察防止把 spawn/adoption 竞态当退出。

默认 shell close 使用 SIGHUP；交互 shell 可 trap SIGTERM。关闭须同时处理进程与 master fd；部分 open 失败也不能仅删除 store 而留下进程或 fd。

## Agent 展示状态不等于自动投递许可

terminal binding 的持久化生命周期（包括 Stop）用于展示，不构成自动输入授权。自动投递许可只存在于 Host 内存；接收方必须同时验证 terminal attribution token、当前 launch 与 agent session 绑定，以及 producer 在 launch 内单调递增的 source deliverySequence。旧 hook 缺少序号时仍可保持展示兼容，但自动投递状态必须视为 unknown，不能仅凭 Stop 补发许可。

生产者序号必须在事件发生时同步预分配，再交给 detached sender；不能等后台进程调度后取号。端点 failover 与同请求重试复用原序号和 payload，预分配缺失或失败的 adapter 只能 display-only，禁止 sender 晚补号制造新因果顺序。

入口可忽略已被更新证据超越的无 native session 原始 Start，但必须同时满足 terminal attribution token 有效、当前 binding 的 workspace/launch/provider 一致，以及正安全整数 deliverySequence 不大于已记录序号。忽略发生在 Store/Guard mutation 和生命周期广播之前，既不恢复 clean/idle，也不授予原生生命周期或输入权限；它只防止认证的旧通知抹掉较新证据。不同身份、无效 token、更新序号或带不同 native session 的事件仍走原有保护，不能泛化为忽略所有不可信事件或让工具事件清除草稿。

可信且新鲜的 Start 建立工作区间，同一绑定中其后的新鲜 Stop 只有在输入缓冲仍有 clean 证明时才允许一次自动投递。permit 在发送队列头部一次性 claim，随后不能重复使用；Host 重启不从持久化展示状态恢复许可。

人工输入和 clear 除撤销已有 claim 外，还在同一 launch 以非等待锁采样 producer watermark 作为 cutoff。采样前已生成的迟到 Start/Stop 只能更新展示，不能恢复许可；采样失败保持 barrierPending fail closed，成功恢复也必须等待其后完整可信的新 Start→Stop。持久 floor 只防止旧事件回潮，不是重启后的许可，替换 launch 不继承旧 cutoff。

独立 draft latch 同时约束自动投递和明确人工中断。工具完成、PermissionResult 或下一次模型调用可更新 working 展示，却不能证明用户已提交草稿；尤其 agy PreInvocation 和旧 Gemini AfterTool 都可能被扁平化为 Start。只有可信且越过人工输入水位的真正用户提交才可清除 dirty，不能只按归一后的 Start 名称判断。

Host 仅在 daemon 真正新建 PTY、尚未向手工输入暴露的同步 fresh 回调中登记初始 clean，并绑定本次预分配 launch 身份。existing/adopt/旧记录重试和 Host 恢复都没有这份证明；登记有界、首绑定消费、失败或退出精确清理，重复登记不能抹掉草稿。人工 WS `input`、`writeInput`、手动 `send` 在首 hook 前也要撤销 pending clean；send 在入队前及队头再次撤销，不能因当时没有 binding 而漏掉输入。

自动与手动发送都在入队前、队头及延迟 Enter 前复核当前 session registry；自动发送还在这些边界复核绑定和许可，且组合许可在等待 Mail reservation 后、任何字节写入前再次检查。session 被替换、adoption 后 registry 不再指向原实例，或许可失效时停止后续写入。串行与复核只能收窄交错窗口，不构成绝对零竞态或安全隔离保证。

错误返回中的 `inputStaged: true` 表示文本或 Enter 可能已经部分或全部进入 PTY，不代表完整提交成功。写入后许可失效、session 更换、部分写入失败，甚至单独 Enter 的传输失败都可能返回此标记；自动许可已经被消费，调用方必须核对终端现状，不能盲目重试文本或 Enter。

明确人工中断使用独立 attempt，不复用 idle permit 或抢 broker writer。它要求可信 busy 区间、clean draft、producer 水位与同 launch 的前台 native executable/进程启动身份；取消后须等新鲜可信的 Interrupt 证据，再复核身份与输入状态。取消键写入起结果就可能不确定，超时或断线不自动重发。具备这些内部原语不等于所有 provider 可用；公开 Mail 的平台 capability 由 `teamwork/execution` 约束，`mailInterrupt=true` 也不替代逐目标证明，更不表示收件人已 read/ACK 或任务完成。

前台 executable 与 CLI stop 共用内核路径读取，不以可伪装的 ps comm/argv[0] 作为身份。可执行路径匹配仍须结合当前 PTY 的前台组、进程启动身份和 launch 归属，并在受保护写入旁重新核验；内核路径快照本身不授予输入许可，也不消除 PID 复用竞态。平台读取机制与失败关闭规则由 `runtime/local-host` 约束。

## 尚无输出不等于就绪

无 ready marker 的 shell 启动不能把尚未输出当作 prompt 已经可读。输出静默计时仅在已经观察到输出时启动；此前没有输出，则由首个输出开始计 quiet。独立 cap 始终有效，防止持续输出或永不输出把启动无限挂起；cap 到达只进入有界的后续 fallback，不证明 prompt ready。

ungated initial command 先等 quiescence，再输入并验证完整 echo；启动脚本的 stdin reader 可能吞掉字符，line editor 也可能在 kernel 已回显后清空 typeahead。必须识别缺失、损坏及命令自身无法解释的 echo 后输出，失败先重新等待静默，再 Ctrl-U 重输。重试耗尽后仍有有界的 blind Enter fallback；命令太短或非 ASCII 开头而无法构造 probe 时跳过 echo 验证，但仍执行静默等待，不能宣称所有命令都获得 echo 保证。

quiescence 与 command echo verification 共用 single-slot echoProbe，同一会话不得并发运行，否则一个等待器会覆盖另一个。延迟输入与 Enter 前须复核取消、退出和 session registry 身份；defunct 或写入失败后停止注入并清理尚未消费的 staged 文件，不能让 teardown 后的定时回调继续发命令。

取消必须通过 cancelLaunchWait 主动结算等待，并释放 callback、echoProbe 与 timers，使从未输出的已 dispose 会话立即进入 defunct 检查和 staged 清理，而非等到 cap 才继续。即使 ready marker 阶段已经结束，也必须先取消 launch waiter，不能因 shellReadyState 不再 pending 而跳过。

## detach 与画面恢复

WS detach 只移除该 client 的 focus/size 约束。多个可见 client 取最小尺寸，全部 hidden 保持已有 PTY 尺寸。CLI Ctrl+] 只 detach 并恢复本地 TTY/raw mode；unexpected transport close 不能显示为远端 shell 已退出。

seq catchup 需要同 epoch、仍在 retained range 且不跨 resize。不可信 anchor 必须 reanchor 并请求运行程序重绘；不能向已有 screen 注入猜测快照或重复旧字节。

历史名 createRelaySocket 是直连终端和 eventBus 共用的重连实现。每次拨号重新构造 URL 和 PSK，默认不缓存断线 send，防止重连后重放旧输入。probeRelayHost 对非 `/hosts/<id>/` 直连路径立即返回 null，不发云请求。watch interest 可在重连后重新订阅，这不授权重放终端输入。

## 端口观察不授权任意杀进程

port-scanner 以 PTY 进程树归属 listener；脱离树的后台进程通过继承的 JEDV_TERMINAL_ID 归属。每轮重新读环境，PID/PPID 不能证明进程实例，缓存会把复用 PID 误归给旧终端。异步扫描回写需确认 session 实例未更换；inspection 失败不表示所有进程退出。

killPort 必须重新读当前进程表、listener 和 terminal/workspace 归属，不杀 terminal 根 shell。无法 inspection 或归属不符则拒绝；OS inspection 与基于 PID 发信号仍非原子，只能收窄窗口，不能宣称绝无 PID race。

host 重启后 reaper 仍登记无人 attach 的活 daemon 终端，退出后 unregister 端口归属，避免 dev server 遗漏或泄漏。Chat 进程共享的端口登记不能因 synthetic terminal 消失就误删。

源码锚点：`SessionStore.ts`（PTY/replay）、`terminal.ts`（detach/resize/catchup）、`reaper.ts`（恢复与结束）、`port-manager.ts` 和 `detached.ts`（端口归属与重新验证）。
