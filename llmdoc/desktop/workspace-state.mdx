# 工作区视图状态与活资源

pane 是视图容器，terminal 是活执行资源。布局所有者必须先理解终端的 detach 与 dispose 区别；不能因为 pane 被移走、恢复或重排，就销毁它指向的 shell。

## close、remove 与恢复

panes store 用 close 表示需要发出资源关闭回调的用户操作，用 remove 表示仅从当前容器拆下。transfer 保留 pane identity 和 split 子树，以 remove 从源容器移出，再放入目标。restore 清除失效引用也用 remove。把这些路径改成普通 close 会把纯布局变化升级为进程副作用。

布局 adapter 等待 saved layout 和 live terminal 列表都 ready 才恢复。恢复前用户已经编辑的布局不能被旧 snapshot 覆盖；同样不能将尚未加载的空会话列表当作“全部终端死亡”。有意从布局移出的活 terminal 以 detached identity 记住，避免 reconcile 又自动加回。

共享 terminal query 的成功状态必须来自实际查询；关闭菜单中的空 props 只是局部显示 fallback，不能以 initialData 写成全局成功快照。否则布局消费者会把尚未取得的会话列表误当权威空集，删除 saved pane 或 detached 记录。侧栏位置来自对应工作区的布局投影，不从 transport attached 推断已在标签或右区；未加载布局时保持位置未知。

新 Agent 标签发现先等待 sessions/bindings 就绪并建立基线，只为同 Host/workspace 后续出现且有 live binding 的新 terminal 添加视图。既有后台或显式 detached 终端不会被重新打开，身份与双区容量预算耗尽时保持后台。追加必须保留 active Tab 和输入焦点；panes 的 focus:false 只抑制 focusRequest，不能据此假设活动标签未切换。右区 open 状态还须在实际 panel handle 挂载后同步尺寸，不能以位置元数据代替可见区域。

发现器还以有界的 provider/config/native session 记忆跨越 terminal 消失与替换，防止后台会话的继任者被误当全新 Agent 自动开 Tab。已有 terminal 的身份优先，不因 binding/list 到达顺序反转而改变；预算耗尽时停止自动发现，不淘汰旧身份后将其重开。这份记忆只抑制自动呈现，不授权旧→新 rebind；原位恢复仍必须走 strict successor 查询。

resumed 事件只触发重查，旧→新 terminal 映射由同 Host/workspace 的 strict successor 查询确认，且后继须已出现在会话列表中。迟到结果还要复核连接、store、旧 pane 对象与 Tab；用户已关闭、移动或改绑的视图不被覆盖。已有后继的重复 pane 只 remove，不 close PTY。重连补查和 saved layout 恢复都只读取这条映射，不触发 resume mutation 或新建进程；查询失败或已知后继暂未可见时保留 saved 并提供重试，期间用户编辑优先。Host 的列表查询成功不等于完整 daemon 快照，单次缺席不授予创建替代会话的权限。

保存按顺序合并 pending snapshot；失败保留可重试的数据与显式错误，不能把本地内存已更新当作已持久化。主进程按注册 window key、host identity、workspace 分区；回环端口变化规范为同一本地 host，私网 origin 则保持独立身份。

本地 pane CLI 经 main 定向到一个已注册 renderer subscription，无需云登录。main 的 pending/subscriber 与 renderer 队列/去重均有界，关闭窗口、退订、连接更换或过期请求显式失败；同窗口重复订阅不能双执行。renderer 从本机 Host 核对 workspace/terminal，按 host/workspace retain 布局 store，实际操作前复核并等待保存 flush；失联或超时可能结果未知，需查看布局而非盲重试。focus 不能切离私网 Host 或绕过未保存文件守卫。keepTerminal/move 仅 remove，普通 close 的资源终止仍由既有 Host 入口唯一负责；不支持的旧 browser/chat/pages 或细粒度文件动作明确拒绝。

## logicalHostId 与 transport endpoint 分开

本地 Host 使用稳定逻辑标识，私网 Host 按已验证 origin 独立命名；端口变化、transport client 和 Electron provider 重建可以继续使用新 client，但不能因此改变 Team 选择或请求身份。不同私网 origin 不据此合并，PSK/client machineId 也不作为共享 UI 身份。

Team Mail 草稿由 renderer 内存 store 按 `[logicalHostId, teamId]` 隔离，而非 endpoint key 或 localStorage/SQLite。它只保留原文、收件人、dedupe/request 和 pending，最多 32 个 scope；非 pending 闲置 24 小时清理，pending 身份受保护。成功或手清可回收空项，权威在线列表中的删除/归档立即清理，初始加载/查询失败不当作删除证据。旧回调不复活已清理 scope，重连只恢复供用户明确发送，不自动重放。具体业务归属由 `teamwork/execution` 约束。

## 有界且受校验的持久层

shared decoder 检查 envelope 大小、split 深度、tab/pane 引用、终端唯一性及左右区域一致性。旧 browser 形状只用于清除历史存档；解码后删除对应 pane，不能作为恢复旧功能的入口。

main 串行写入，异步提交前再次验证窗口与连接身份；失败回滚内存状态。窗口数量、每窗口上下文和总字节预算都有限，达到上限应明确失败，不能静默丢弃用户布局后返回成功。

renderer localStorage 是同步启动、共享配额且跨版本存活的小状态层。每个 writer 必须登记、给出界限和删除者；实体键不能无限增加。删除 feature 时同时登记 DEAD_KEYS，由启动 sweep 回收旧 profile 数据。仅移除 writer 会永久遗留用户数据，配额保护也不是扩大集合的许可。

## 看板与读回执的事实来源

工作区看板优先使用 archive 与 merged PR 状态，再根据未结束的 Agent binding、read receipt 和打开 PR 选择工作列。usage 日志和成本估算不是工作区执行状态的来源。

读回执由 main 持久化后广播；正时间戳单调推进，null 表示删除。renderer 将未确认的本地 mutation 叠加到服务端 snapshot，ack 后才移除 pending，防旧订阅覆盖刚发生的阅读动作。跨 host 或跨 workspace 的回执不能共用键。
