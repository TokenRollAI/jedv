# 分发与更新完整性

源码版本、独立 CLI、桌面安装包和自动更新 feed 是不同完整性边界。构建成功不证明资源齐全，生成安装包不等于发布，而 source tag 也不证明签名、notarization 或更新元数据已经可用。

## 版本兼容规则

CLI 与 host-service 使用相同 plain MAJOR.MINOR.PATCH；发布准备保持 desktop、CLI 与 host 对齐。底层版本校验还允许 CLI/host 在 desktop 同一 major/minor 内领先 patch，不能将这个兼容能力误写为三个值永远严格相等。pty-daemon 有独立版本与协议生命周期。

变更版本或最小 host 支持条件时，应共同评审 manifest adoption、客户端兼容和发布脚本，而非只改某个 package manifest。具体当前值由 manifest 与 check:versions 回答，知识文档不保存版本快照。

## standalone 与 Electron 的原生运行时

独立分发将 Bun 编译的 CLI、Node host wrapper/runtime、原生依赖和 host/chat 迁移作为整体。只复制 bin/jedv 不能提供完整本地 host。目标 OS、architecture、Node ABI 与 native addon 必须匹配；在 Electron 下重建的 addon 不能直接替换独立 Node 分发依赖。

开发 Node 集成测试也不能在共享 node_modules 上 rebuild 来修 ABI。隔离 runner 从已安装且打过补丁的源码复制 native addon，并实体复制会被 gyp 写入的依赖；它为本次 Node ABI 构建临时副本，将 resolver 传到测试子进程，同时隔离应用与 Agent 配置 home，结束只清理本次目录。仅父 runner 使用副本而子进程仍解析共享 addon 不构成隔离。

桌面打包同时维护 bundler external、真实文件 materialization、打包 copy 和 ASAR unpack。通过文件系统动态加载的模块或迁移不能因 bundle 成功就省略。更新任一清单时需追踪实际运行时解析路径，否则开发 symlink 可用的依赖会在安装包中失效。

安装包只携带 production dependencies。编译产物仍通过 require/import 动态加载的包，以及独立启动的 ACP adapter，都必须落在这一依赖闭包；只在开发环境可解析不足以证明可分发。runtime dependency 检查读取编译后的 main/preload 与 adapter 声明，变更宏编译、external 或依赖归类后要保留该检查。资源复制 helpers 同时决定迁移与 Agent templates 的实际落盘路径，不能因删除旧功能而连带删掉保留运行面所需资源。

## 打包、签名与发布边界

手动 packaging workflow 默认生成 unsigned artifacts；显式选择 signed 时，必须先具备 Developer ID 与 Apple 公证凭据，导入临时 keychain、强制代码签名并公证，再通过 codesign strict verify、有效 TeamIdentifier、stapler 和 spctl 验证。签名分支结束后清理临时 keychain；缺凭据或验证失败不能悄悄降级为 unsigned 成功。

签名选择与发布权限相互独立。两种打包路径都禁止自动 publish，只上传构建 artifacts；包、manifest 与更新 feed 的一致性仍需在实际发布时验证。生成签名或未签名产物都不代表发行已发布。release 分支的推送同样进入 CI，不能只依赖 main 分支的检查覆盖发行准备。

## updater 的成功与失败证据

updater 先区分开发、未安装、缺元数据、环境禁用与受支持运行面。macOS 本体签名检查仍要求 strict verify、有效 TeamIdentifier 与非 ad hoc 身份；签名决定自动下载和安装资格，不阻止已打包且具有更新元数据的 unsigned build 查询真实 feed。

SDK 默认关闭 autoDownload 和退出时自动安装。检查前确认本体签名，通过后才开启自动下载，继续使用 electron-updater 原生签名保护；unsigned 保持 autoDownload=false，也不接受下载事件进入 ready。unsigned 的“已最新”、可用版本和检查失败都必须来自真实检查结果；发现新版本时提供打开 Releases 页的手动下载动作，不能调用安装器。

feed 必须给出合法版本，并明确确认较新发行或无更新。没有结果、无法解析版本或返回非更新版本不是“已最新”。错误应脱敏、区分签名/feed/网络/磁盘与发行问题，不能靠下载进度判断安装已获准。

安装只从 ready 状态经用户确认和 prepare 后进入；窗口 close/beforeunload 可取消退出，取消须恢复 ready 与可重试状态。不能设置退出时无条件自动安装来绕过窗口保存与用户取消。下载/签名等失败按类型清理相应缓存，不能把有问题的产物继续留在可安装状态。

## 权威锚点

- `packages/cli/scripts/build-dist.ts`、`apps/desktop/runtime-dependencies.ts`：原生依赖与文件布局。
- `scripts/release/lib.ts`：版本兼容校验；`.github/workflows/package-jedv.yml`：可选签名公证与不自动发布的产物边界。
- `apps/desktop/src/main/lib/auto-updater.ts`、`auto-updater/runtime.ts`、`signature.ts`、`quit-lifecycle.ts`：检查、下载、安装权限与退出状态机。
- `apps/desktop/src/renderer/components/UpdatesPill/update-state.ts`：真实检查结果与手动更新动作的展示契约。
